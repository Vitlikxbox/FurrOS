# FurrBoot — свой загрузчик FurrOS

Решения автора (допрос 10–11.11.2026). GRUB уходит из FurrOS полностью.

## Что решено
| Вопрос | Решение |
|---|---|
| Название | **FurrBoot** |
| Загрузчик | свой, с нуля, программа для UEFI |
| GRUB | на 1–2 релиза остаётся запасным (на UEFI), потом убрать |
| Старые ПК с BIOS | простой запасной загрузчик (Limine) в цветах и с обоями FurrOS |
| Вид | как на макете `mockup/01-main.png`, `02-snapshots.png`, `03-kernels.png` |
| Персонажи | Пикси на карточке FurrOS, Данёк в углу с облачком (только наш арт: логотип, Пикси, Данёк) |
| Анимации | да: появление карточек, подпрыгивание выбранной, лапки при запуске |
| Звук | **нет** |
| Темы и обои | да: несколько палитр/обоев, выбор из настроек FurrOS |
| Мышь | да: клик по карточкам мышью и тачпадом (если UEFI отдаёт указатель) |
| Автозапуск | **10 секунд, всегда FurrOS** |
| Язык | язык системы (RU / EN / PL / ES), меняется вместе с языком FurrOS |
| Язык кода | **Rust** (`uefi-rs`, цель `x86_64-unknown-uefi`) |

## Пункты меню
- FurrOS (ядро по умолчанию)
- Снимки системы (Btrfs + Snapper): только для проверки, изменения пропадают после перезагрузки
- Windows (если есть)
- Безопасная графика (`nomodeset`)
- Другое ядро: FurrOS / обычное Arch / Zen / LTS
- Настройки UEFI, Перезагрузка, Выключение
- `E` — правка параметров запуска

## Технические ограничения (проверить при разработке)
- UEFI сам читает только FAT: ядра и initramfs лежат на FAT-разделе `/boot` (~2 ГБ, создаёт установщик).
- Снимки: ядро каждого снимка надо копировать на этот раздел (как это делает limine-snapper-sync) — следить за местом.
- Шрифты вшиты в программу: только свободные (Dela Gothic One, Nunito — OFL), Segoe нельзя.
- Secure Boot пока выключен (как и сейчас); подпись — отдельная задача.

## Статус (11.11.2026, ночь)
Готово и проверено в VirtualBox (UEFI, 1920×1200), `test/run.sh`:
- главное меню как на макете, анимация карточек, отсчёт 10 с → сам запускает FurrOS
- запуск ядра Linux с initramfs (EFI stub, `initrd=`) — ядро Arch 7.2 стартует
- экран снимков (прокрутка, метки, карточка снимка), экран ядер
- E — правка параметров запуска, F1 — помощь, Esc — назад
- Windows: запуск bootmgfw.efi (проверено подставным .efi)
- «Настройки UEFI» — перезагрузка прямо в настройки прошивки
- язык/тема/часовой пояс из `\loader\furrboot.conf`, записи BLS из `\loader\entries\`

Не проверено: мышь (в прошивке VirtualBox нет драйверов мыши вообще — см. WORKLOG), реальный Windows, реальное железо.

Ночь 11.11 (подробно — WORKLOG.md):
- дизайн v2 «разворот комикса» (DESIGN-v2.md), все экраны проверены по скриншотам, в т.ч. 1024×768
- рисование на целых числах: кадр 6–16 мс вместо 155 мс
- Boot Loader Interface systemd (`src/bli.rs`): `systemctl reboot --boot-loader-entry=auto-windows`, `bootctl set-oneshot/set-timeout/status`, `systemd-analyze`, `LoaderDevicePartUUID` для gpt-auto-root
- выбор режима экрана с правильными пропорциями; в `furrboot.conf` можно задать `resolution 1366x768`
- F12 — диагностика (прошивка, экран, мышь, BLI, скорость кадра)
- T — тема (6 штук), запоминается в EFI-переменной FurrBootTheme
- автопроверка загрузки: новое ядро получает 3 попытки, после 3 неудач подряд FurrBoot сам запускает запасное (systemd-bless-boot подтверждает удачную загрузку)
- польские буквы в шрифте, однобуквенные слова не висят в конце строки

Настройки `\loader\furrboot.conf`: `timeout`, `default`, `lang`, `theme`, `tz-offset`, `resolution`. Переменные systemd (LoaderConfigTimeout, LoaderEntryDefault, *OneShot) важнее файла.

## Дальше (обновлено ночью 12.11.2026)
1. **Установщик — сделано** (`backend.py`: `bootloader()` + `furrboot()`), выбор автоматический, в «Итоге» установщика есть строка «Загрузчик»:
   - UEFI, весь диск и рядом с Windows на Btrfs: FurrBoot — первая запись, GRUB остаётся запасным (своя запись «FurrOS», на весь диск ещё и `\EFI\BOOT\BOOTX64.EFI`);
   - UEFI рядом с Windows с шифрованием (отдельный ext4 `/boot`): только GRUB — на общем EFI нет места для копий ядер;
   - BIOS: Limine (п. 3), GRUB не ставится;
   - если FurrBoot не записал меню, он не становится первым.
   Пакет furrboot собирает `tools/build_repo.sh` из `bootloader/furros`, на ISO он в копии [furros]; в онлайн-[furros] — после публикации репозитория (ждёт автора).
2. Реальный ПК автора: 0.2.0-3 + linux-furros работают (лог 4): прямой вывод 21 мс против 264 мс через Blt, драйвер Btrfs, оценка загрузки good, NVIDIA через nvidia-open-dkms.
3. **BIOS: Limine в цветах FurrOS — сделано.** `furrboot-install --bios DISK --esp DIR`; меню `limine/limine.conf` пишет `furrboot-update` (на английском: шрифт Limine только ASCII); обои `furros/limine-furros.png`. Разметка BIOS: BIOS boot 1M + FAT 1G + корень. Хук `96-furrboot-limine.hook` заново ставит Limine после обновления пакета.
4. Live-образ: UEFI-меню = FurrBoot по умолчанию (`tools/build.sh`), BIOS — syslinux с заставкой FurrOS.
5. Автотесты на новом ISO (UEFI/BIOS/дуалбут/шифрование) — ночь 12.11, итоги в `D:\FurrOS\NIGHT-TASK-2026-11-12.md`.
